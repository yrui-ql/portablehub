# 主界面设计与演进规划

> 类型：ux ｜ 状态：current ｜ 权威：是 ｜ review_by：2027-01-15
> 建立：2026-10-18 ｜ 最后更新：2026-10-18 ｜ 版本：v1（v0.2.2 落地第一版）

## 定位

PortableHub 是「便携软件的中枢」，不是应用商店、不是启动器平台：

- **唯一目标**：在自己的便携软件目录里，**3 秒内找到并启动**目标程序；
- 不做联网下载/自动更新/账号体系/云同步；
- 界面要能承受「几十到几百个应用」而不失控；
- 零配置可用：首次打开不做任何设置也能按来源自动组织。

## 现状问题（v0.2.1）

| 问题 | 现象 | 后果 |
|---|---|---|
| 平铺网格 | 所有卡片一屏排开，无分组、无筛选、无排序 | 应用一多就靠肉眼扫，找不到 |
| 无「最近/常用」 | 每次都要重新找 | 高频应用启动路径不短 |
| 无视图切换 | 只有中号网格 | 名称长的应用被截断，密度不可调 |
| 无批量操作 | 自启/移除只能逐个右键 | 整理成本高 |
| 搜索结果无分组 | 命中的卡片平铺 | 结果多时同样难扫 |

## 设计原则

1. **搜索是第一入口**：`/` 聚焦、输入即过滤，键盘完成 90% 的操作；鼠标只是补充。
2. **分组即导航**：默认按「来源」自动分组（盘符 + 前两级目录），左侧导航一眼看到全部与各组数量。
3. **零配置可用，再逐步可定制**：自动分组先跑起来；用户想改时再引入自定义分组/标签，不强迫整理。
4. **信息密度可调**：网格/列表、显示密度、图标大小都应可切换（后续阶段）。
5. **状态可预期**：选择、过滤、分组、搜索的组合结果始终一致；空状态给出下一步动作。
6. **不写私密**：分组推导只用路径，不把本机路径写进仓库；用户自定义分组属于用户配置。

## 分阶段规划

### P1 · 来源分组导航（v0.2.2，本次）

- 左侧 `分组` 导航：全部 + 按来源自动分组（local 组 + 盘符/两级目录组），显示数量；
- 「全部」视图按组显示分区标题与数量；
- 搜索与分组叠加；保留现有选中/键盘/右键/编辑/自启行为；
- 发现结果也按来源目录分组（REQ-0021）。

判据：100 个应用时，首屏能看到分组与数量；任一应用 ≤2 次点击（分组→卡片）或 1 次搜索命中。

### P2 · 视图、排序、最近使用

- 网格 / 列表视图切换，列表含名称、来源、自启状态；
- 排序：名称 / 最近启动 / 添加时间；
- 「最近使用」「常用」分区（按启动记录，记录只存本地）；
- 密度设置（紧凑/标准）；搜索历史与 `↑↓` 在结果间导航。

判据：常用应用从打开到启动 ≤1 次点击；列表视图下 200 个应用可滚动定位。

### P3 · 组织能力（用户自定义）

- 自定义分组与标签，可把应用拖入分组；自动分组作为默认，用户覆盖优先；
- 批量选择（框选/Ctrl 多选）+ 批量操作（自启、移组、移除、隐藏）；
- 重复项检测与清理入口（按真实路径检测，给出一键合并/移除）；
- 配置需要 `schemaVersion: 2`（用户分组/标签/固定项入 config，迁移兼容 v1）。

判据：用户可在 1 分钟内把自己的 30 个应用分成 3 组；重复项可一键处理。

### P4 · 外观、引导与托盘

- 现代风格主题（浅色/深色）、主题预览；
- 首次运行引导（选目录 → 扫描 → 导入/分组确认）；
- 空状态插画与可操作提示；托盘菜单加入常用应用与「显示/隐藏」。

### P5 · 便携增强

- 配置导出/导入（迁移到新机器/新目录）；
- 备份与恢复（config + 主题 + 图标缓存）；
- 启动参数模板、工作目录预设（批量设置）。

## 关键设计决策

| 主题 | 选择 | 理由 |
|---|---|---|
| 默认分组 | 按来源自动分组（盘符 + 前两级目录），不写 config | 零配置可用；路径已包含用户组织信息 |
| local 组 | 程序目录（`Apps\` 相对路径）单独一组，置顶 | 与外部来源区分，最稳定 |
| 分组持久化 | P1 不持久化；P3 起用户自定义入 config v2 | 避免为一个视图状态改 schema |
| 视图状态 | 会话内保存，重启回「全部」 | 简单、可预期 |
| 启动记录 | P2 引入，只存本地 `_cache`/config，不联网 | 隐私与便携 |

## 开放问题（需要用户决定）

1. 默认分组粒度是否合适？如果 `E:\Tools\系统增强\...` 下的应用希望按更细的二级目录分，可调为三级。
2. 更想要「列表视图」还是「可调密度的网格」？
3. 需要「最近使用」还是「固定置顶」优先？
4. 是否接受自定义分组/标签（需要 config v2 迁移，属于较高风险变更，会单独做）。

## 验收方式

- 自动化：分组纯函数单测 + e2e（分组导航、过滤、搜索叠加、选择/启动不回归）；
- 手工：100 个应用场景下按「分组→卡片」「搜索」两条路径各走一遍，记录点击/输入次数。
